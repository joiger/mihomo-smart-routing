# Проверка Clash Verge, Nova и Antigravity Unlocker — 9 октября 2026

## Подтверждённые причины

- Clash Verge: обновление подписки 8 октября в 21:47 завершилось `tls handshake eof` при прямом подключении и двух резервных попытках. Само сообщение не устанавливает, какое оборудование оборвало TLS. При текущей проверке загрузка той же подписки через локальный прокси 7897 вернула HTTP 200.
- Nova: в `opera.log` многократно отмечена ошибка проверки сертификата: сертификат Microsoft вместо `am0.sec-tunnel.com`. Из-за этого Opera-прокси не обслуживал CONNECT. Пустые ответы WSS и резервные попытки Telegram сопровождали сбой. Сообщения «POST не поддержан, нужен CONNECT» означают несовместимый тип запроса к локальному реле, поддерживающему SOCKS5 и HTTP CONNECT.
- Nova: в 01:32 детектор обнаружил туннель Mihomo и приостановил Nova. Это предусмотренная защита от одновременного перехвата трафика двумя приложениями.
- Unlocker: региональные ошибки Google 400 возникали на маршруте «свой прокси». Служба переключилась на «напрямую», после чего зарегистрировала сотни успешных ответов. Резервные встроенные выходы продолжали отвечать таймаутами, VPN-маршрут — ошибками разрешения имени. Эти сообщения нельзя считать доказательством отказа рабочего прямого маршрута.
- Монитор Aegis использовал сохранённый отчёт с рабочего стола как текущую телеметрию и повторно трактовал старые ошибки как действующие. Это вызывало ложный диагноз и повторные попытки исправления.

## Выполнено

- Для активной подписки `aegis` включено `with_proxy: true` в локальном `profiles.yaml`. Рядом сохранена резервная копия. Изменение требуется подхватить при следующем запуске Clash Verge; уже запущенный интерфейс может сохранять прежние параметры в памяти.
- Диагностика и монитор Aegis теперь учитывают порядок событий, возраст ошибок и свежий `AGUnlocker/gate.json`. Исторический отчёт больше не определяет аварийный статус. Успешный ответ после ошибки снимает её; недоступность одного запасного маршрута не означает отказ всех маршрутов.
- Повторные автоматические действия монитора ограничены интервалом диагностики.

## Проверка

- Подписка через Clash: HTTP 200.
- Google Cloud Code через Clash и системный маршрут: HTTP 404 для корневого URL, то есть TLS и HTTP работают. Это не проверка авторизованной генерации модели или отсутствия регионального отказа на конкретном API-запросе.
- 23 теста `python -m unittest discover tests`, 5 тестов `python test_telemetry.py`, 6 тестов `node --test tests/test_incident_triage.mjs`: успешно.
- Новый диагностический запуск не обнаружил свежей региональной ошибки.

## Что осталось

- Запущенный монитор Node работает с повышенными правами. Windows отказала в его остановке; изменения кода применятся после его ручного перезапуска. Остальные приложения и сетевые службы не перезапускались.
- Серверы Opera и резервные выходы Unlocker остаются недоступными. Их восстановление не подтверждено; текущая рабочая сеть обслуживается Clash. Проверка TLS сохранена.
- Исправление несовместимых POST-запросов требует установить их источник и настройки клиента. Перевод такого клиента на SOCKS5/CONNECT должен проверяться в активной сессии Nova, которая сейчас приостановлена из-за TUN.

Ранее существовавшие изменения в рабочем дереве сохранены.
